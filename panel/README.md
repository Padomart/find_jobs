# Панель вакансий

Десктоп-приложение для macOS: очередь вакансий из `en/` и `ru/` с решением по каждой
(оставить / удалить / изменить / отправить в JobSync) и запуск скриптов поиска с историей.

Go + [mygo](https://github.com/egoist/mygo) (системный WKWebView, без cgo), фронтенд — Svelte 5 + Vite,
хранилище — SQLite (`modernc.org/sqlite`, чистый Go).

## Запуск

Нужны Go 1.27+ и Bun (`brew install go oven-sh/bun/bun`). Из папки `panel/`:

```bash
bun install
```

```bash
bun run dev
```

`dev` собирает отладочное приложение «Job Panel Dev», запускает его и пересобирает при правках
(Go — перезапуск, Svelte — горячая замена).

Сборка `.app` и `.dmg` в `build/darwin-arm64/`:

```bash
bun run build
```

Готовое приложение можно перетащить в «Программы». Папку проекта оно находит само (сохранённый путь,
`FINDJOBS_ROOT`, родительские папки, `~/Documents/Work/find_jobs`), иначе — Настройки → «Выбрать папку…».

Проверки:

```bash
bun run test        # go test ./core — хранилище, идемпотентность импорта, маскирование секретов
```

```bash
bun run typecheck   # svelte-check
```

Без окна, из терминала (то же ядро; удобно для проверки и скриптов):

```bash
go run ./cmd/panelctl -root .. list -status new
```

Команды `panelctl`: `import`, `list [-status S] [-q TEXT]`, `show -url URL`, `act -url URL -status
shortlisted|dismissed|new`, `edit -url URL [-title T] [-company C] [-desc D]`, `send -url URL [-resend]`,
`run boards|ru`, `budget`.

## Как устроено

```
panel/
├── core/              ядро без mygo: SQLite, импорт, отправка, запуски, окружение (+ тесты)
├── main.go            оболочка mygo: сервис Panel для страницы, события, трей, уведомления
├── cmd/panelctl/      то же ядро из терминала
├── src/               Svelte: App, views/{Inbox,Overview,Runs,Settings}, mygo.ts (генерируется)
└── mygo.config.ts     имя, идентификатор, сборка
```

Ядро (`core.App`) не знает про mygo: оболочку можно заменить локальным сайтом, обернув те же методы
в `net/http`. `panelctl` — пример второй оболочки.

**Данные** — `state/panel/panel.db` в проекте (`state/` уже в корневом `.gitignore`).
Таблицы `jobs` (оригинальные поля, правки пользователя отдельно: `edit_title`, `edit_company`,
`edit_description`, `notes`; статус, очередь, даты), `runs` (скрипт, аргументы, время, код выхода,
сколько импортировано, лог), `settings`.

**Импорт** — `en/out/jobs_noats.json`, `en/out/boards.json` (вакансии внутри бордов),
`ru/out/jobs_ru.json`. Ключ — URL: повторный импорт не создаёт дублей и не трогает статус, правки и
заметки; дубли внутри файла схлопываются (остаётся копия с более полным описанием и оценкой).
Вакансии из `state/jobsync_ledger.json` (журнал `common/jobsync_push.py`) помечаются «В JobSync»,
кроме удалённых в корзину. Импорт идёт при старте, после каждого успешного запуска и по кнопке в Настройках.

**Статусы** — новая / оставлена / в JobSync / в корзине. «Удалить» — в корзину, «Вернуть» — обратно
(отправленная возвращается в «В JobSync»), насовсем — только «Очистить корзину» в Настройках.

**Отправка в JobSync** — через `common/jobsync_push.py`, протокол не дублируется: панель пишет
временный JSON выбранных вакансий в формате их исходного файла, с вашими правками, в
`state/panel/outbox/`, и запускает скрипт с `--check-existing` (или `--resend` для обновления уже
отправленной — upsert по URL, без дублей). Результат берётся из журнала: что попало в `pushed`,
то «В JobSync». Лимит (60 вызовов в час на всё; скрипт тратит не больше 50) считается по тому же
журналу; что не влезает — ставится в очередь и уходит само, когда лимит освободится (проверка раз в 2 мин).

**Запуски** — `python3 en/find_boards.py` / `ru/find_ru_jobs.py` с флагами из Настройки (по
умолчанию — из README этих папок), живой лог, остановка (SIGTERM группе процессов), история, после
успеха — импорт и уведомление. «Здоровье источников» разбирается из лога последнего запуска.

**Секреты** — только из `.env`, передаются только в окружение скриптов. В интерфейсе — «задан / не
задан»; в логах и сообщениях значения `.env` (и адрес JobSync) заменяются на «JOBSYNC_URL» и т. п.

## Горячие клавиши (Входящие)

| | |
|---|---|
| `j` `k` / `↓` `↑` | следующая / предыдущая |
| `s` | оставить |
| `d` / `⌫` | в корзину |
| `r` | вернуть из корзины |
| `e` | изменить (сохранить — `⌘↵`, отмена — `esc`) |
| `o` | открыть оригинал в браузере |
| `↵` | отправить в JobSync (с подтверждением) |
| `u` | отменить последнее действие |
| `/` | поиск |
| `пробел` | выбрать для пакетных действий, `esc` — снять выбор |
| `⌘1`–`⌘4` | Входящие, Сводка, Запуски, Настройки |

## Что есть в JobSync MCP

`tools/list` у вашего сервера: `add_job`, `add_jobs_batch`, `find_job`, `update_job`, `add_question`,
`save_match_result`, `save_match_results_batch`, `review_resume`, `save_resume_review`.
Обновление есть (`update_job`, а панель обновляет через `add_jobs_batch` с `upsert`), **удаления
нет** — удалить вакансию из JobSync можно только в его интерфейсе.

## Известные ограничения

- Имя бандла латиницей (`Job Panel.app`): `codesign` падает на кириллице в имени; в Dock и меню —
  «Панель вакансий» (`CFBundleDisplayName`).
- У вакансий из `boards.json` нет описания: `find_boards.py` не сохраняет текст вакансий бордов.
- Приложение подписано ad hoc, не нотаризовано: при первом запуске из `.dmg` — правый клик → «Открыть».
- `PANEL_VIEW=overview|runs|settings` открывает приложение сразу на нужном экране (для скриншотов).
